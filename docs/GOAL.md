# GOAL: AUTONOMOUS NEURAL COMPANY (ANCOS)
## A Self-Managing, Self-Expanding, Multi-Agent Engineering Organization

---

## 1. PRIMARY OBJECTIVE

The overarching mission of **ANCOS** (Autonomous Neural Company Operating System) is to architect, operate, and progressively evolve a fully autonomous, persistent, multi-agent AI software engineering enterprise.

This is **not** a basic chatbot, a simple collection of pre-scripted agent prompts, or a rigid workflow automation tool. 

ANCOS exists to receive complex, high-level, real-world human objectives (e.g., *"Build and deploy a complete production-grade distributed e-commerce platform"*), autonomously break them down into structured projects, recruit or dynamically spawn specialized AI employees, allocate dedicated sandboxed Linux desktops (Docker + VNC) to them, coordinate execution, conduct adversarial testing and independent QA, convene autonomous executive and department boardroom meetings, continuously learn from failures and discoveries, and recursively evolve its own architecture, tooling, and model configurations under strict human sovereignty.

---

## 2. THE FIVE FOUNDATIONAL PILLARS

```
┌────────────────────────────────────────────────────────────────────────┐
│                        ANCOS FOUNDATIONAL PILLARS                       │
├────────────────────┬────────────────────┬──────────────────────────────┤
│ 1. Central CEO     │ 2. Dynamic Desktop │ 3. Autonomous Digital        │
│    Orchestration   │    Employees       │    Boardroom & Meetings      │
│ (Boss AI Brain)    │ (Docker + VNC)     │ (Daily Standups, Minutes)    │
├────────────────────┴────────────────────┴──────────────────────────────┤
│ 4. Independent Verification & QA       │ 5. Recursive Self-Evolution   │
│ (Zero Success-by-Decree)               │ (Self-Learning & Upgrade)     │
└────────────────────────────────────────┴──────────────────────────────┘
```

### Pillar 1: Central CEO Orchestration (Boss AI)
- Intelligent technical company director acting as Chief Executive Officer.
- Evaluates incoming human objectives for feasibility, complexity, and resource requirements.
- Constructs hierarchical project DAGs (Phases → Tasks → Subtasks).
- Delegates work based on verified employee skills and balanced resource loads.
- Maintains high-level company awareness without micromanaging sandbox mechanics.

### Pillar 2: Dynamic AI Employee Workforce with Dedicated Desktops
- Employees are not abstract API calls; each active employee has a full Linux container environment with an interactive desktop accessible via noVNC/VNC.
- Employees possess explicit profiles: unique ID, title, department, personality, communication style, system prompt, authorized toolset, and persistent memory.
- **Skill Verification**: Skills are not merely asserted; they must be empirically verified through real execution and independent testing before being marked as verified in an employee's profile.

### Pillar 3: Autonomous Meetings & Digital Boardroom
- The Boss AI autonomously schedules and conducts structured meetings (daily standups, architecture reviews, incident post-mortems, executive briefings).
- Employees participate using model-backed intelligence, reporting factual progress, evidence, blockers, and dependencies.
- Automated generation of structured meeting minutes, decisions, and tracked action items.

### Pillar 4: Independent Verification & Zero Success-by-Decree
- No work is declared complete based on an employee's self-assertion.
- Dedicated QA and Security verification engines independently execute tests, inspect code, check acceptance criteria, and validate runtime receipts before tasks are closed.

### Pillar 5: Continuous Self-Learning & Recursive Self-Evolution
- The system continuously observes its own operational metrics, identifies capability bottlenecks, formulates improvement hypotheses, executes sandboxed experiments, and stages releases.
- Retains automatic rollback capability if performance regresses.
- Enforces strict human approval boundaries on security, permissions, and financial commitments.

---

## 3. SUCCESS CRITERIA & NON-NEGOTIABLES

1. **Deterministic Execution**: Zero simulated progress or fake progress percentages. All execution logs must reflect real container processes, tool exits, and network receipts.
2. **Strict Sandboxing**: Containers must never mount the host Docker socket (`docker.sock`) or run with `--privileged`.
3. **Persistent Knowledge**: Organizational knowledge survives restarts across structured relational data, vector embeddings, and procedural skills.
4. **Human Authority**: The human owner retains ultimate sovereignty with an instantaneous emergency stop mechanism and approval gates for irreversible actions.
