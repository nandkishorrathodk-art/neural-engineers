# ANCOS NEURO phased execution plan

This plan preserves the phase numbering and acceptance scope from the ANCOS NEURO master mission. The architecture is shared across phases, but a phase is accepted only with its own evidence. Code presence and mocked unit tests do not satisfy runtime acceptance.

**Plan alignment checked:** 2026-11-06
**Source:** user-provided ANCOS NEURO phases master brief (NEURO-0 through NEURO-13).

## Dependency order

1. Keep NEURO-0 evidence current and resolve P0 authority/lifecycle gaps in NEURO-1 through NEURO-3.
2. NEURO-4 requires an isolated Docker/broker runtime; NEURO-3 mode contracts and independent verification must be available before its acceptance mission.
3. Establish verifiable execution and provenance before accepting NEURO-5 through NEURO-10 learning, GUI, engineering, and governance outcomes.
4. NEURO-11 must render backend truth and remain honest about unavailable/stale data; it does not substitute for backend execution acceptance.
5. NEURO-12 controls apply throughout every phase, and its fault/recovery acceptance runs after the relevant lifecycle paths exist.
6. NEURO-13 is the final integration gate and cannot be inferred from per-module tests.

## Operating gates

- Keep employee identity persistent; session/container lifetime is separate.
- Keep owner, worker, verifier, approver, and broker credentials distinct; no employee can self-grant access.
- Terminal/GUI execution must flow through the restricted broker and authorized task-mode contract.
- A worker submission remains unverified until a separate verifier's evidence-backed receipt passes.
- Run relevant regression, failure/recovery, security, and integration checks for every slice; distinguish mocks from runtime evidence.
- Record commit, exact commands, environment, exit status, duration, and artifacts. Keep blocked acceptance gates open until their external dependency changes and real proof is captured.
- Preserve unrelated dashboard worktree changes and user data while advancing backend/roadmap slices.
