## Latest implementation evidence

- Foundational worker/recovery commits `455f752`, `395f53d`, roadmap-doc commit `1e6f897`, and the isolated verifier-consumer slice are included in the current release sequence. The verifier slice has focused evidence but no Docker runtime receipt.
- The opt-in terminal worker lifecycle and verifier rejection retry/backoff/fencing paths have focused tests. The manifest/verifier focused run passed **36 tests**; the resource scheduler plus cognitive integration run passed **18 tests**. Scoped Ruff and mypy passed for verifier work; Docker profile parsing passed. No Docker image/runtime was available.
- Resource scheduling now accepts `ResourceLeaseRepository` for durable per-host slot leases, carries fencing tokens in allocation receipts, heartbeats active claims during scheduler requests, releases claims on provisioning failure and confirmed shutdown, and preserves slots/claims when termination is not confirmed. Container CPU/RAM limits follow the selected profile. Three DB-backed integration cases cover competing schedulers, fencing token increments, failed provisioning cleanup, and fail-closed termination; scheduler/cognitive/resource tests passed **21 tests**. `ANCOS_RESOURCE_POOL_ID` scopes shared slots to one host pool; all scheduler processes sharing that pool must set the same stable value. This is injectable support, not yet proof that a live service wires it or that stale containers are recovered after process loss.
- A verifier rejection is persisted, consumes configured retry budget, increments the task fence, backs off before a retry, and sets terminal `FAILED` on exhaustion. This fixes a stuck-task transition; it does not by itself provide a live runtime receipt.
- A separate verifier consumer replays only the submitted attempt's declared `pytest`/`npm test` commands through a verifier-authenticated, attempt-fenced Core API endpoint. The broker runs them in a disposable network-disabled container with a read-only employee-workspace volume and a 300-second timeout, then removes the sandbox. A bounded SHA-256 path/size snapshot is captured at verification time; it is not a task-start diff or artifact correctness proof. Criteria remain restricted to an exact test-only allowlist.
- Latest complete full suite before the final resource-pool namespace tweak: **408 collected; 396 passed, 12 skipped, zero failed, 5 warnings**. The final namespace/config adjustment is covered by the 21-test focused scheduler run, full Ruff, and Compose parsing. One live restricted-broker test skips only when broker credentials are absent; remaining skips include optional model/runtime cases. This local green regression does not prove Docker-backed runtime acceptance.

No phase advances to accepted until its acceptance mission has the required evidence. A mock, skipped test, or API/module alone is not an acceptance receipt.
